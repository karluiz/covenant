# 3.27 — Evals experience overhaul (draft + run)

## Goal

Make draft/run evals trustworthy and usable: a run you can stop, results you
can inspect (why did it fail?), evals you can manage in-app, and suites that
finish in minutes instead of half an hour — starting from the P0 bug where the
installed app can't find the `claude` CLI at all.

## Context (what exists today)

- Harness: `crates/app/src/canon_eval.rs` — `claude -p <scenario>` in a temp
  sandbox, read-only tools + deny-list, 120s timeout. Each eval runs TWICE
  (with-unit arm + bare baseline arm) and judges both → 2 CLI runs + 2 judge
  calls per eval, strictly sequential. 8 evals ≈ 30 min worst case.
- UI: `ui/src/canon/evals.ts` — draft drawer (LLM-drafted scenario/rubric
  pairs, checkbox + textareas, "Write N evals" chip) and a fixed
  bottom-right progress panel (`.canon-eval-progress`, single global
  instance) with per-eval dot + slug + one-line truncated reason.
- Storage: `crates/canon/src/eval.rs` — `evals/<kind>/<name>/<id>.toml`
  authored files; `eval-results.json` upserted by eval id (last-write-wins).
- Judge + drafter both ride `Role::Summary`. Transcripts are dropped after
  judging. Registry push: skills-from-registry only, silent on failure.

## Phases

### P0 — broken or blocking

1. **Login-shell PATH for the harness** — DONE in this worktree.
   `Command::new("claude")` inherited launchd's minimal PATH in the installed
   app → "claude CLI not found on PATH", 0/8 skipped. Fix: inject
   `login_shell_path()` (already used by `canon_import_skill`), cached in a
   `OnceLock`, into both `claude_available()` and the harness spawn.
2. **Cancelable runs.** New `canon_cancel_evals` command + abort flag checked
   between arms; panel ✕ becomes "Stop run" while running, second click
   dismisses. Backend must stop spawning + judging within one arm.
3. **Persist transcripts + per-eval detail.** Write both arms' transcripts to
   `.covenant/canon/eval-runs/<kind>/<name>/<eval-id>.json` (scenario, rubric,
   verdict, reason, duration, model, both transcripts, ran_at). Clicking a
   result row opens a detail view. Secret-mask before writing.
4. **No stale verdicts.** A timeout/error today writes nothing, so the prior
   run's verdict keeps showing as current. Mark the stored row
   `stale: true` (or clear it) and render it distinctly in summaries.

### P1 — the experience

5. **Progress panel v2.** Expandable rows (full reason, duration, with/without
   verdict pair); show which arm is running ("baseline · 3/8"); reopenable
   from the unit row while a run is live; per-unit stacking instead of the
   single global instance; survive window reload (re-attach by reading run
   state, or at minimum warn a run is orphaned).
6. **Evals manager.** A list under each evaluable unit: view/edit
   scenario+rubric, delete, add manually. Draft drawer: editable ids and an
   explicit overwrite choice on collision (today re-drafts are silently
   dropped because write never overwrites).
7. **Bounded parallelism.** Semaphore (2–3 concurrent harness runs) in
   `canon_run_evals`. Keep judge calls serialized if provider rate limits
   demand it.
8. **Baseline cache.** The bare sandbox is identical across runs — cache
   baseline verdicts by scenario hash; invalidate never (scenario text is the
   key). Halves re-run cost.

### P2 — control

9. **Cost preview + scoped runs.** Confirm card shows the arithmetic
   (N evals × 2 arms × ≤120s + 2N judge calls); "run one eval" from the
   manager list; baseline arm opt-out toggle for quick iteration.
10. **Model provenance.** Pin `--model` on `harness_args`; store executor +
    judge model ids in `EvalResult`; optional dedicated Judge role so
    draft-strong/judge-cheap is configurable.
11. **Timeout coverage.** Harness timeout becomes a setting; wrap judge LLM
    calls in a timeout (today a hung provider hangs the run).

### P3 — memory

12. **Run history.** Append per-run records instead of last-write-wins;
    surface "last run Nd ago" + pass-rate delta on unit cards.
13. **Honest sharing.** Non-skill kinds say "results stay local"; registry
    push failure surfaces a toast instead of `tracing::warn` only.

## Out of scope

- Hardened container sandbox (tracked separately in canon_eval.rs header).
- Multi-executor harness (codex/copilot) — claude only.
- Registry-side eval display changes (Plan B shipped; see
  project_eval_plan_b).
- Editing the judge/draft prompts from the UI.
- Windows PATH probe (`-ilc` fails there; inherited PATH fallback stands).

## Acceptance criteria

- [ ] Installed .app (Finder-launched) runs a suite with `claude` in
      `~/.local/bin` — no "not found on PATH" skips.
- [ ] A running suite can be stopped from the panel; no further
      `canon-eval-progress` events arrive after stop.
- [ ] Clicking a failed eval shows rubric, judge reason in full, and the
      agent transcript.
- [ ] A timed-out eval never displays the previous run's verdict as current.
- [ ] Re-drafting an existing id offers overwrite instead of silent drop.
- [ ] 8-eval suite wall time drops ≥2× with parallelism + baseline cache
      (measured on the horizon suite).
- [ ] `cargo test --workspace` and `npm test` green; new behavior has
      regression coverage (parsing, cancel, stale marking, cache).
